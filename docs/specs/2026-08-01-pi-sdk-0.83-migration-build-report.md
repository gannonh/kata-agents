## Implementation

- Migrated direct Pi dependencies and lockfile entries to exact `@earendil-works/pi-*@0.83.0` versions.
- Migrated agent sessions, model runtime and registry APIs, OAuth, Bedrock, tool, and compatibility-catalog imports.
- Removed GPT-5.6 supplemental model definitions. OpenAI API and ChatGPT/Codex model metadata now comes from Pi 0.83's native catalog.
- Preserved provider identity through model resolution and renderer-facing DTOs. Renderer modules receive only `ModelDefinition` capability data and do not import Pi SDK modules.
- Derived capabilities from Pi's native map semantics, including native `max`, and map Kata `max` directly to Pi `max`.
- Regenerated the ignored Electron Pi-agent-server resource and added subprocess smoke verification.

## Review and manual verification

Independent spec-compliance and code-quality reviews passed with no Critical or Important findings. The final quality review retained one non-blocking recommendation to make the provider DTO test data-driven across all three GPT-5.6 models; native registry coverage already exercises Sol, Terra, and Luna.

Credential-backed OAuth, Bedrock authentication, and Electron provider-menu UAT were not run because no credentials or E2E session were supplied.

The repository-wide `bun test` command does not complete in this environment. It reports one unrelated existing failure in `packages/shared/src/agent/__tests__/workspace-slug.test.ts`: the empty-path case expects its fallback but receives the current workspace slug, then remains open after the shared `pi-agent-quiescence.test.ts` cases. Those tests and implementations are outside the migration scope and unchanged by the Pi 0.83 commits. The focused migration suite passes independently.

The generated Electron Pi-agent-server resource remains intentionally ignored by the repository's existing generated-resource rule; the build path regenerates it before packaging.
