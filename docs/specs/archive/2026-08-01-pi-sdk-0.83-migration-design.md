# Pi SDK 0.83 migration

## Status
Implemented

See the [build report](2026-08-01-pi-sdk-0.83-migration-build-report.md).

## Context

The application exact-pins the retired `@mariozechner/pi-*` package family at `0.73.1`. That is the final release under that npm scope. The installed Pi CLI uses `@earendil-works/pi-*@0.83.0`, whose model catalog includes current GPT-5.6 metadata and native `max` reasoning support.

The user explicitly requested the latest Pi upgrade and reconciliation of resulting integration issues.

## Decision

Migrate every direct Pi dependency atomically to `@earendil-works/pi-ai`, `@earendil-works/pi-agent-core`, and `@earendil-works/pi-coding-agent` at exact `0.83.0` versions.

Use `@earendil-works/pi-ai/compat` where the application intentionally relies on the legacy catalog helpers (`getProviders`, `getModels`) while retaining the new package family. Preserve renderer boundaries by keeping Pi SDK imports outside renderer modules.

Use Pi 0.83 model metadata as the reasoning-level source of truth. Remove GPT-5.6 supplemental entries once the native catalog supplies the same models. Preserve application persistence values, but map Pi `max` directly to native Pi `max` rather than collapsing it to `xhigh`.

## Scope

- Update all package manifests and `bun.lock` together.
- Migrate source imports, type imports, OAuth access, and tests to the new package scope and supported compatibility entry points.
- Reconcile Pi agent-server registry setup with the new APIs.
- Derive supported reasoning levels from native `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, and `max` metadata.
- Remove obsolete app-side Pi `max` aliasing and GPT-5.6 catalog supplementation.
- Regenerate and smoke-test the Electron Pi-agent-server bundle.

## Non-goals

- Changing non-Pi provider reasoning behavior.
- Adding live network model-catalog refresh.
- Altering credential storage formats or connection-selection precedence.

## Acceptance criteria

1. All direct Pi dependencies use `@earendil-works/*@0.83.0`; source and lockfile contain no live `@mariozechner/pi-*` dependency or import.
2. Existing Pi integration compiles against the new package APIs, including agent sessions, registry/model resolution, OAuth handling, tool definitions, event adapters, and Bedrock support.
3. The model catalog is sourced from Pi 0.83 and exposes native GPT-5.6 Sol, Terra, and Luna entries without Kata-maintained duplicate supplemental definitions.
4. Model-specific reasoning options mirror Pi 0.83 `getSupportedThinkingLevels` semantics, including native `max`. For GPT-5.6 Luna, OpenAI API exposes `off, low, medium, high, xhigh, max`; ChatGPT/Codex exposes `off, minimal, low, medium, high, xhigh, max`.
5. Pi runtime mapping sends `max` as native Pi `max`; models without native `max` omit it from the renderer controls and Pi retains final request-level clamping.
6. Renderer capability lookup continues to resolve bare and `pi/`-prefixed model IDs without importing Pi SDK modules.
7. Focused package tests, shared/server-core/Pi-agent-server/Electron typechecks, i18n checks, subprocess build, and Pi bundle smoke verification pass.
8. Release notes and the OKF bundle record the migration and any residual manual credential-backed verification need.

## Build handoff

1. Update dependency manifests and install `@earendil-works/pi-*@0.83.0` together.
2. Use red-green tests to lock native GPT-5.6 reasoning metadata and native `max` runtime behavior.
3. Migrate imports and reconcile compile/runtime breakage using Pi 0.83 compatibility APIs where appropriate.
4. Remove duplicate supplemental GPT-5.6 metadata only after native-catalog tests pass.
5. Rebuild the bundled Pi server, execute the verification matrix, and obtain independent spec and code-quality reviews.

None.
