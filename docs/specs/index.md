# Specs — Roadmap

The remaining rebrand work is consolidated into one complete brand-transition plan. The old Project A/C/D split is superseded by the active spec below; implementation can still ship as multiple smaller PRs under that plan.

## Active

* [2026-07-26-git-github-worktrees-v1-design.md](2026-07-26-git-github-worktrees-v1-design.md): V1 design for Current checkout/New worktree sessions, a Changes review panel with line feedback, safe commit/push/GitHub PR actions, and local/remote worktree lifecycle parity. Status: Approved; **Phases 1 (Start isolated) & 2 (Review changes) complete and Phase 3 (Share work) building** behind `KATA_FEATURE_GIT_WORKSPACE_V1`. Phase 2 landed the Changes header affordance (changed-file count + additions/deletions), a right-sidebar Changes panel (overlay drawer at narrow widths) bound to the focused session, a flat changed-file list with explicit clean/non-Git/binary/oversized/missing/loading/error states, unified/split diff via `ShikiDiffViewer`, diff-line feedback (old/new sides) with a session-scoped pending-comment store, stale-on-fingerprint-change detection, and a single deterministic follow-up send through the existing message pipeline. Phase 3 adds the safe commit/push/GitHub-PR controls (AC12–AC16): a pure 14-rule action-state resolver + independent menu builder (`@kata-sh/shared/git`), `RepositoryService` publishable/base-delta counts, a `GitActionService` (selected-file `GIT_INDEX_FILE` commit transaction, fast-forward-only pull, push + upstream, structured partial success, never force-push/reset/rebase/merge), a `GitHubCliService` `gh` adapter (capability/auth, PR lookup, PR create) tested against a fake `gh`, real flag-gated commit/pull/push/PR RPC handlers under the mutation lock, and an adaptive header `GitActionControl` with Commit/PR dialogs, default-branch confirmation, and partial-success/disabled explanatory states. Renderer subscribes on open / unsubscribes when the last surface closes, with ≤3s coalesced polling → ≤5s external-change bound. See ADR [2026-07-29-server-owned-managed-worktrees.md](../adrs/2026-07-29-server-owned-managed-worktrees.md). **Status: Implemented — Phase 4 (Manage lifecycle, AC17–AC21) complete.** Phase 4 added: server-side mutation identity revalidation (worktree top-level vs checkout path + shared Git common dir + expected branch) blocking commits in conflicted/merge-in-progress states and on externally switched managed branches; PR base-ref authority (persisted managed base ref wins over client input); actionable `gh` setup guidance in the header control; a `DeleteSessionDialog` offering managed-worktree removal as a separate, force-confirmed choice that names uncommitted/unpushed work and is blocked while another owner remains; a composer checkout recovery/blocked badge for missing/drifted worktrees; and a serial headless-server flow test proving remote-ownership parity. Build report: [2026-07-26-git-github-worktrees-v1-build-report.md](2026-07-26-git-github-worktrees-v1-build-report.md). Real-GitHub UAT and the macOS `@git` E2E GUI flow are deferred to Verify.
